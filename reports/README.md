# Reports — what was measured, and what wasn't

This directory holds ControlPlane's measurement artifacts. Every number here
is generated by a committed script from a committed input file — none is
hand-typed. `make report` regenerates `summary.json` and the reports below
from whatever is actually in `decisions.jsonl`. This file is a plain-language
map of what's in the directory, not a new source of numbers.

## What was measured

| Report | What it measures | Corpus | Status |
|---|---|---|---|
| `baselines.md` (P04) | B0–B5: six systems (no gate, rule-only, auth-only, LLM-judge, trace-grounded, ControlPlane) scored on the same gold set | `bench/gold_set.jsonl` (P03) — 150 cases: 140 non-ambiguous + 10 ambiguous | Current, complete |
| `robustness.md` (P08) | What happens when the system of record itself is wrong — SOURCE-UNRELIABLE coverage, and the record-error crossover rate | Same 140-case gold set, `orders.db` delivery-date corruption sweep | Current, complete |

## What the B4/B5 result actually establishes

B4 and B5 run the **identical** ControlPlane pipeline; the only difference
is where evidence comes from — B4 from the agent's own retrieved trace, B5
from a fresh, independent query against the live system of record. On the
140 non-ambiguous gold cases, B5 is correct on all 17 cases where B4 is
wrong, and B4 is never correct where B5 is wrong (McNemar exact two-sided
p = 1.53e-05; accuracy 100.0% vs. 87.9%, a 12.1-point gap, 95% CI on the
difference [6.6%, 19.7%] via cluster bootstrap over source-order clusters).

**16 of those 17 discordant cases are `stale_policy_context` cases** — B4
grounds its decision in a policy clause the agent retrieved that has since
been superseded; B5 queries the live clause. The 17th is a distractor case.

This is evidence about **one failure mode — retrieval staleness — on one
gold set**. It is not evidence that record-grounded verification is
universally superior to trace-grounded verification, and it should not be
read that way. It says: when the fact a claim depends on has changed since
it was retrieved, asking the record directly catches what re-reading the
same stale context cannot.

## P08 negative result: no verifier architecture survives a wrong record

`robustness.md` (P08) corrupts a growing share of `orders.db`'s
delivery-date field and re-runs the full gate at each corruption rate.
ControlPlane's accuracy on the gold set stays at or above the frozen B4
baseline (87.9%) only below a **≈10.6%** record-error rate (cluster
bootstrap 95% CI [10.6%, 44.7%]); above that rate, ControlPlane's own
accuracy falls below what a trace-grounded checker achieves without
touching the record at all. This is stated as a negative result, not
softened: **ControlPlane inherits the system of record's errors.** It does
not claim to catch a wrong record — it claims to be exactly as right as the
record, and this is the rate at which that stops being good enough. See
`docs/limitations.md` for the SOURCE-UNRELIABLE boundary this implies.

## Major limitations

- **External validation is incomplete.** tau2-bench C1 (a governance-free
  baseline on a third-party benchmark) is done; C2/C3 — the actual
  ControlPlane-vs-baseline comparison on that external benchmark — are not
  yet built or run. Until they land, every quantitative result above is our
  own internal, single-domain, single-gold-set evidence.
- **Generalization beyond this gold set is not established.** The 150-case
  gold set is synthetic, single-domain (retail refund servicing), and its
  50 ALLOW cases sit on only 5 distinct source orders — every confidence
  interval above resamples order clusters, not cases, for exactly this
  reason.
- **Adversarial robustness is not measured.** P08 corrupts records by a
  deterministic, disclosed procedure; it is not an adversarial red-team
  exercise, and no claim is made about a motivated adversary crafting
  inputs against the gate.
- **Concurrency is measured, not optimized.** `latency.md` section H shows
  per-call latency degrading substantially under a 10-worker thread pool
  (SQLite connection-per-call and a serialized receipt-append lock are the
  named causes); this is reported as-is, not tuned away.

## What is NOT established

- That ControlPlane is "universally better" than any baseline — the B4/B5
  result is scoped to retrieval-staleness failures on this gold set (see
  above).
- That tau2-bench validates ControlPlane externally — it does not yet,
  pending C2/C3.
- That the system is production-ready, secure against adversarial input, or
  robust outside the scenarios measured here.
