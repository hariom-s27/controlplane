But the two new docs — `docs/experiment-audit.md` and `docs/retired-figures.md`

- *"`bench/gold_set.jsonl` now exists — 150 cases..."* — it does not exist in this tree.

**The disclaimer that would make this honest exists — but only in `README.md`.**
Its new section states plainly: *"Those two documents are unchanged historical
artifacts from commit `b4ef009...`. ... This publication commit merges the
disclosures and retires the public claims; it does not merge those repair
implementations, and it did not generate replacement results."* Verified
accurate — `b4ef009` is real, locally reachable, and matches that description.
But `docs/experiment-audit.md` and `docs/retired-figures.md` contain **no such
caveat internally** (`grep` for `b4ef009` / "not merged" in both files: zero
hits). A reader who opens either doc directly — the obvious path, since
README links to them — will reasonably read "Current... Real... measured" as
established fact about the public repository. It is not.

> **Resolution:** this is not a case of `00`–`15`'s conclusions being
> superseded by real progress becoming public. It is a **new, more serious
> defect**: the original repo state at least stated its numbers *honestly as
> tautological*; the current public docs state *specific alternative numbers
> as real* without the one sentence that would make that true.

### 22. Biggest reviewer vulnerability
Not "every accuracy figure is a tautology" (the code at least states that
honestly). It is: **the two documents the project's own README directs a
reviewer to for "what changed" contain numbers that cannot be reproduced from
anything in the repository, without disclosing that inline.** Five minutes and
an `ls` finds this, and it reads worse than the original tautology because it
looks like a retroactive justification rather than a disclosed limitation.

## 3. TL;DR — what to fix before touching GitHub again

1. **`docs/experiment-audit.md` and `docs/retired-figures.md` currently
   overclaim.** They report specific numbers ("0.92 with the check, 0.755
   without", "mutation score 0.60", latency percentiles, receipt-size stats)
   as `Real` / `Current`, but none of the supporting files exist in the
   public tree and the committed code still produces the *old* tautological
   numbers. Either add the same provenance disclaimer `README.md` already
   carries ("historical artifact from `b4ef009`, not merged, no replacement
   results generated here") into both files, or delete the specific numbers.
2. **`MODIFY` still executes unmodified arguments** — `Decision.modified_args`
   is declared but never assigned; an `UNVERIFIABLE` verdict on
   `send_document` sends the document unchanged. ~3 lines to fix.
3. **`scripts/gate_check.py` still can't run** — 3-vs-4 tuple unpack against
   `servicing_agent.py::propose()`. 1 line to fix; it's the only artifact that
   answers "was the demo staged?"
4. **A missing order/policy record still crashes instead of escalating** —
   no `try/except` around the Zen predicate call.
5. **All of `b4ef009`'s work (gold set, baselines, evidence ablation, P06
   tau2 preflight, CI) is not on `origin/main`.** Decide, explicitly, whether
   to merge it before making any further public claim that depends on it.

Everything else in this file is supporting detail for those five points.
