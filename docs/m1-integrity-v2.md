# M1 integrity record v2 (13 Nov 2026)

> **Historical record (last changed 2026-11-13).** This file records work as of that date and is not maintained. Numbers, file paths and status statements in it are not current claims; current numbers are in `docs/claims.yaml` (checked by `tests/test_claims.py`) and corrections to frozen reports are in `docs/errata.md`.

`docs/m1-integrity-v2.sha256` records the sha256 of 38 protected and frozen files.
It was generated by `scripts/integrity_record.py --write` at commit `0381b68`, not by hand.

## Why v1 went stale

`docs/p06-post-p02-integrity.sha256` (v1, 30 Aug 2026, base `b4ef009`) hashed raw bytes:

- 8 of its 14 rows were hashed from CRLF copies. The content is unchanged, but an LF checkout
  gives a different raw hash.
- The `controlplane/intercept.py` row predates commit `986b65e` (C/I/D safety hardening).
- Later authorized changes: D-M1-01 (`00ca015`) changed `intercept.py`, `manifest.py` and
  `tests/test_manifest_hardening.py`; D-M1-02 (`356ec58`) changed `manifest.py` again.

v1 is kept unchanged as history. It is not a row in v2. Instead the test
`test_v1_integrity_record_is_kept_unchanged_as_history` pins its own hash.

## What v2 covers

- The 14 v1 paths, every PROTECTED file (`controlplane/intercept.py`, `manifest.py`, `decide.py`,
  `schemas/manifest.schema.json`, `manifests/*.yaml`, `tests/test_manifest_hardening.py`) and the
  tracked FROZEN files that v1 did not cover (`bench/label.py`, `bench/extraction_gold_v1.jsonl`,
  the other committed `reports/*` files).
- Hashing: files with suffix .py .md .json .jsonl .csv .yaml .yml .txt .sha256 .toml .sh .ps1 are
  hashed with every CRLF replaced by LF (no other change); all other files (the two .png
  reports) as raw bytes. A CRLF checkout therefore gives the same hashes as an LF one.
- Status per row: `UNCHANGED_SINCE_V1` (v1's hash matches the content in LF or CRLF form),
  `CHANGED_AUTHORIZED` (a v1 path changed since v1), `NEW_IN_V2` (not in v1; baseline `0381b68`).
- Authority: every commit since `b4ef009` that touched the file, mapped to its decision
  (D-M1-01, D-M1-02, D10, or pre-M1 public history in `v1.0-round2`). The script stops on an
  unmapped commit.

## How to check

    python scripts/integrity_record.py --check

It exits 1 if a listed file is missing or its hash differs. It needs no git history.
`tests/test_integrity_v2.py` runs the same check in the test suite.
