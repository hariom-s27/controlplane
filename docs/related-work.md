# Related work

## Agent trace and temporal grounding

**AgentLTL.** Laïla Elkoussy and Julien Perez's *AgentLTL: A Trace-Verification Framework for Measuring, Enforcing, and Training Procedural Compliance in Tool-Using LLM Agents* ([arXiv:2607.02599v1](https://arxiv.org/abs/2607.02599), 2026) specifies first-order temporal constraints over tool-call traces and supports online prefix gating as well as offline evaluation. Its grounding condition checks whether entities occur in prior tool outputs and states that its atomic propositions use no external data sources. ControlPlane does not add comparable temporal expressiveness: `decide()` is per-action and stateless. Its narrower difference from AgentLTL is the evidence path used for selected checks: configured resolvers query records at adjudication rather than treating prior trace output as the authoritative witness.

**LedgerAgent.** Md Nayem Uddin, Amir Saeidi, Eduardo Blanco, and Chitta Baral's *LedgerAgent: Structured State for Policy-Adherent Tool-Calling Agents* ([arXiv:2606.20529](https://arxiv.org/abs/2606.20529), 2026) is the closest problem-level overlap in the supplied source review. Its abstract describes a structured ledger built from user interactions and tool returns, with state-dependent constraints checked before environment-changing calls. ControlPlane likewise targets stale or incorrect context before execution. The distinction is narrower than the shared motivation: LedgerAgent's described state is curated from the interaction and observations, while ControlPlane's registry path re-queries configured record stores. The supplied review inspected the LedgerAgent abstract, not the full paper, and recorded inconsistent date metadata; no stronger comparison is made here.

**Current and shared state.** Vikas Reddy, Sumanth Reddy Challaram, and Abhishek Basu's *Reason Less, Verify More: Deterministic Gates Recover a Silent Policy-Violation Failure Mode in Tool-Using LLM Agents* ([arXiv:2607.07405](https://arxiv.org/abs/2607.07405), 2026) uses deterministic, read-only pre-execution gates over a proposed call and current simulated database state. Maurits Kaptein, Vassilis-Javed Khan, and Andriy Podstavnychy's *Runtime Governance for AI Agents: Policies on Paths* ([arXiv:2603.16586v1](https://arxiv.org/abs/2603.16586), 2026) permits prospective policy decisions to depend on a proposed action, partial path, identity, and shared governance state. These systems rule out a broad claim that current or external state at a runtime gate is a ControlPlane distinction. The repository's more specific design focus is checking call content against the configured transactional record it concerns, including a currently effective version in the policy-store path.

## Agent governance and policy enforcement

**AEGIS.** Aojie Yuan, Zhiyuan Su, and Yue Zhao's *AEGIS: No Tool Call Left Unchecked — A Pre-Execution Firewall and Audit Layer for AI Agents* ([arXiv:2603.12621v1](https://arxiv.org/abs/2603.12621), 2026) interposes a policy firewall on the tool-execution path and records an Ed25519-authenticated, SHA-256-chained audit trail. It overlaps ControlPlane on interception, composable policy checks, intervention, and auditability. ControlPlane's HMAC-authenticated receipt is not hash-chained and provides a weaker integrity design. The colliding identifier `2603.16938` refers to a different Aegis paper and is not evidence for these claims.

**Open Agent Passport.** Uchi Uchibeke's *Before the Tool Call: Deterministic Pre-Action Authorization for Autonomous AI Agents* ([arXiv:2603.20953](https://arxiv.org/abs/2603.20953), 2026) describes synchronous interception, declarative authorization, and a cryptographically authenticated audit record. The supplied review verified the abstract but did not inspect the linked specification repository. At the level established by that abstract, Open Agent Passport asks whether a principal is authorized to perform a call; ControlPlane focuses on whether selected call content agrees with resolved records. Both occupy a pre-execution boundary, so the boundary itself is not a differentiator.

**C-Trace and AgentCore Policy.** Nafiseh Kahani, Masoud Barati, and Diana Addae's *Runtime Compliance Verification for AI Agents* ([arXiv:2606.19242v1](https://arxiv.org/abs/2606.19242), 2026) incrementally evaluates first-order compliance predicates over typed event traces and can forward, redact, or block. Its intervention structure and runtime interception substantially overlap ControlPlane; its evaluated predicates concern trace-level data-governance obligations rather than reconciliation with transactional records. The official [Amazon Bedrock AgentCore Policy documentation](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy-core-concepts.html) describes deterministic policy enforcement outside agent code before tool access, using Cedar or Dogwood policies. Its documented inputs include identity, tool schema, session events, and guardrail signals. The reviewed documentation did not establish a business-record re-query equivalent, but that absence is not a field-wide claim. The supplied pages also did not establish named `AUDIT` and `ENFORCE` modes, so those mode names are not attributed here.

## Auditable / accountable agents

The official [Amazon Bedrock Automated Reasoning checks documentation](https://docs.aws.amazon.com/bedrock/latest/userguide/automated-reasoning-checks-concepts.html) describes post-generation checking with formal rules and states that the checker does not consult external data. This is a different tradeoff: the AWS mechanism is more formal, while ControlPlane performs pre-execution state predicates over resolved records without a proof of soundness. More broadly, signed or authenticated decision records are established prior-art territory through AEGIS and Open Agent Passport. ControlPlane's receipt is useful implementation evidence for what its gate decided; it is not positioned as a research differentiator.

## ControlPlane positioning

The repository implements a concrete pre-execution composition:

- `ProposedAction.facts_for_predicate()` excludes prose-derived `claimed_*` fields while retaining structural tool-call arguments.
- Registry resolvers obtain evidence from configured SQLite record sources; the policy resolver selects the currently effective row and refuses ambiguous current state.
- Missing, malformed, or unavailable predicate evidence is represented as uncertainty rather than silently passing. Source outages follow the manifest's compensability-specific posture, which may be open or closed.
- The interception boundary maps decisions to execution, refuses `MODIFY` without an explicit argument mapping, applies process-local idempotency, and emits an HMAC-authenticated decision receipt.

These are implementation-grounded properties, not separate demonstrations of research efficacy. The strongest prior-art counterexamples cover each broad mechanism: AgentLTL covers online gating and richer temporal rules; LedgerAgent covers maintained-state policy checks; Reason Less, Verify More covers current-database gates; Policies on Paths covers shared runtime state; AEGIS, Open Agent Passport, C-Trace, and AgentCore Policy cover pre-execution enforcement; and AEGIS and Open Agent Passport cover authenticated audit artifacts. The contribution therefore survives as a design and engineering position rather than a novelty claim.

## Evidence and limitations

This document positions an implementation, not an empirical result. The implementation statements refer to the verified local release candidate `aac3bea9a7a11e8d9da5173d7e7d647f5f607989`; the public baseline remains `6ec4261d374904f55bf5dff1a9855854f1b94819`. The candidate carries the original C/I/D reconciliation from ancestor `986b65e522091cc2d5d2f4ccf571688a095c3529`, the recipient-authorization correction from `dce2e4cc4c0cc1eaae2bc58fc02f5ea7971b65c6`, and the threat-model synchronization at `aac3bea9a7a11e8d9da5173d7e7d647f5f607989`. The off-release P04, P05/A1-A5, P08, and P09 results are not evidence for the current candidate because they have not been rerun against it. P03/M4 remains a future methodology and artifact promotion candidate after targeted correction, not current public evidence. P06 and tau2 results are not used.

A decision-time read is not automatically independent of the agent's information source: in the orders path, the agent workflow and resolver may ultimately depend on the same underlying store. The policy path more specifically demonstrates selecting the currently effective version independently of the agent's asserted version. Both included use cases are synthetic. Regression tests establish the implemented behavior; they do not establish benchmark efficacy, external validity, broad generalization, comparative performance, adversarial robustness, or deployment readiness. The Python boundary can be bypassed by code that does not call it, idempotency does not survive a restart or span processes, receipts are not tamper-evident across entries, and the policy language has no temporal or formal-verification guarantee.

ControlPlane focuses on pre-execution checks of selected proposed tool-call content against configured records re-queried at adjudication, whereas the cited systems describe trace-grounded temporal compliance, interaction-derived ledgers, authorization, broader policy firewalls, and current-state gates. Within that overlapping space, its implementation makes a specific composition explicit: prose-derived assertions are separated from predicate facts, record evidence is resolved at adjudication, and unavailable evidence enters explicit decision handling. The repository demonstrates that composition within its stated synthetic servicing and knowledge-assistant scope, but does not establish broader generalization, external validation, superiority, or production readiness.
